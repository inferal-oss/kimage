October 16, 2026

  • Argo CD chart-version upgrades and compatible downgrades from 0.5.1 onward. A returning older chart automatically delegates to the installed newer operator by digest, preserving the lifecycle lock and resumable journal, without manual catalog selection. Commits: 972d6c8.
  • Copyable Argo CD Applications and installation, configuration, health and retention guidance in the README, handbook and agent essentials. Commits: 0149688, ed016cb.

v0.5.0

October 16, 2026

Added

  • Explicit installation upgrade and compatible rollback commands, with read-only checks, an exclusive Lease, resumable phases and retained storage/credential identity verification. The initial supported transition is 0.4.1 to 0.5.0 and back, without storage or API migration. Commits: 5f480cf.
  • Automatic node membership and native worker reconciliation, with UID-bound serving approvals, administrator node selection and worker pins, and fencing before replacement. Commits: 5f480cf, 28789ba.
  • Read-only kimage status and kimage doctor, including JSON output, pending operations, component readiness, native platforms, retained storage, certificate validity and resource drift. Commits: 5f480cf.
  • Private build diagnostics through kimage logs IMAGE --follow and kimage builds IMAGE, with platform and attempt selection. Completed attempt logs survive build Pod cleanup; each platform retains the latest five attempts with a bounded 64 KiB output tail per attempt. Guides explain access permissions, retry policy, output clipping and progress limits. Commits: 5f480cf, 81140cb.

Changed

  • Recorded eight native lifecycle cases and real mixed-cluster CLI/Helm round trips through actual published 0.4.1, including interruption/resume, native pulls/builds, node eligibility/worker changes, private failure logs and retained-image recovery after uninstall/reinstall. Commits: 9d868b4.
  • After rollback to the published 0.4.1 controller, the documented Helm removal procedure stops its operator and retires its recreated workers before chart removal. Acceptance guards worker identity/specification, recognizes Kubernetes' omitted false defaults, and refuses foreign Kubernetes or Helm owners. Fresh 0.5.0 Helm removal is tested directly. Commits: f0d1475, 2f0abde, b6bab31.

Fixed

  • Guarded Helm transitions coordinate proxy and worker replacement with the predecessor operator, recover interrupted history without immutable Job conflicts, and tolerate transient restart backoff with Helm 4's legacy readiness wait. Ordinary three-way updates preserve Helm ownership and revision history. Commits: 8de46e5, c44d092, c9ecc2d.
  • CLI rollback resume stops partially restarted predecessor components again. Concurrent worker creation is accepted only for the exact owned, non-deleting specification. Uninstall rechecks pending operations and installation identity under its Lease and stops on Lease loss. Commits: 38e9bfb, b02175f, 4cfddd3.
  • Node reconciliation repairs missing ownership on unchanged resources without restarting them or taking over another owner. Worker recovery and operation journals retain installation ownership for chart adoption and cleanup. Required Pod/Job patch access is limited to the operator's system namespace; doctor identifies denied permissions safely. Commits: 088dd85, e5ac231.
  • Existing immutable credential views are verified without rewriting their metadata or requesting additional Secret write permissions. New views receive installation ownership at creation. Commits: eeb6d49.
  • Resource checks compare JSON values across Helm and Rust serialization, preserving manager identity inside worker recovery templates while rejecting unexpected fields and genuine drift. Commits: ed17184, c44d092.
  • Native readiness Jobs track node identity, placement and input images, and fit Kubernetes label limits for every supported installation name. Readiness checks wait through normal worker replacement without accepting ownership or specification drift. Commits: 307f8f0.
  • Build-log snapshots pair terminal phases with final output. Following an attempt waits through startup and bounded transient connection failures, reports gaps, and retains full attempt identities in valid diagnostic Secret names. Commits: 3674da9, 03372fe, 7019062.
  • Builds wait for a replacement worker's Pod and service endpoints before capturing inputs, avoiding empty interrupted attempts during normal worker recovery. Commits: 4409c4a.
  • The BuildKit progress adapter accepts batched records up to 1 MiB, preventing valid output bursts from failing at the old 256 KiB record limit. Total progress stays bounded to 16 MiB and retained text to 64 KiB. Commits: eeb6d49.
  • Candidate acceptance repeats failed-build diagnostics with fresh native Images to catch progress batching and recovery races before image publication. Commits: 9d868b4.
  • Upgrade direction follows semantic version ordering, and native node lifecycle features remain enabled in later releases. Commits: 28789ba.
  • Native diagnostic acceptance tolerates independent stdout/stderr ordering. Cleanup progress and failures expose only bounded metadata; focused lifecycle diagnostics cover both architectures and installation scopes. Commits: 2a36942, 567b50c, 5584c57, 6dce5e8, b2ed1cc, 9ddf0a6.

Security

  • Optional candidate and focused native workflows encrypt failing Helm output to a maintainer-provided certificate; the private decryption key remains outside CI. Focused runs can reuse unchanged native component artifacts and run without capture. Native attempt summaries expose only allowlisted phase and public status codes and bounded metadata. Commits: b02175f, f3a4ca4, 4165667.
  • Diagnostic Secrets carry the predecessor's reserved input marker, so rolling back to 0.4.1 cannot make private build output eligible as an ordinary build input. Commits: ffe7247.
  • Helm upgrade checks reject recovery history that would replay stale credential or build-policy bytes, before stopping components. Commits: 8de46e5.

v0.2.0

October 15, 2026

Added

  • Official GitHub Actions builds now produce a complete Linux/amd64 component bundle, its inventory and checksums, and native Linux/amd64 and macOS/arm64 installers as GitHub release assets. Administrators no longer need to package their own bundle for the supported profile. Commits: ff89753.
  • kimage install runs the standard setup phases in one resumable command. It validates all credential directories before bootstrap writes and avoids repeating bootstrap after a partial handover. kimage-install remains a compatible alias with the same commands. Commits: 68c0540.
  • The installer automatically fetches the exact official release matching its package version, verifies GitHub asset digests, inventory, static executables, and complete OCI graphs, and caches it before Kubernetes access. Commits: ff89753.
  • bundle-fetch prepares an installation or air-gap transfer without kubeconfig; --release, --bundle-cache, and --offline make selection and reuse explicit. Local --bundle with an independently trusted inventory remains supported. Commits: ff89753.
  • Atomic cache installation, bounded archive extraction, process locking, and regression coverage for corrupt, interrupted, unsafe, and incomplete downloads. Commits: ff89753.
  • Release publishing stages verified draft assets, publishes crates through OIDC with safe partial-release resume, then publishes GitHub assets and verifies the real public fetch and offline path. Commits: ff89753, e537b4a, 554c3b7, e93b45d.
  • Updated handbook, README, quickstart, and self-contained agent guidance. Commits: ff89753, 68c0540.
cargo install kimage-control --version 0.2.0 --locked
kimage install --help

The supported Kubernetes/runtime, persistent storage, cached carrier, issuer credentials, and user namespace prerequisites still apply. Automatic fetching changes bundle delivery; it does not broaden the serving-only upgrade window or provide an operator/schema downgrade path. See the handbook.

v0.1.0

October 15, 2026

Added

Initial alpha release for the documented Linux/amd64 Kubernetes runtime profile.

  • Native kimage-install command for API-only bootstrap, verification, recovery, and compatible serving upgrades and rollback. Commits: a048539, 6d6106e.
  • Declarative Image production through pinned BuildKit, verified OCI publication, and retained immutable ImageRelease resources. Commits: a048539.
  • Exact, channel, and readable colon/query range selectors with digest-pinned Pod admission and ordinary kubelet pulls through node-local proxies. Commits: a048539.
  • Separate retained-registry storage and disposable worker cache, two-node delivery/recovery, and an optional independent registry exporter. Commits: a048539.
  • Operational metrics, offline bundle tooling, documented live acceptance evidence, and macOS/Linux test coverage. Commits: a048539, 6d4121e, 6d6106e.

Install the native commands with Rust 1.99.0 or newer:

cargo install kimage-control --version 0.1.0 --locked
kimage-install --help

Cluster installation requires a trusted Linux/amd64 component bundle, TLS credentials, and a supported runtime profile. Builds initially support scratch images and provisioned local inputs. See the compatibility limits.
