DESIRED STATE, ALL THE WAY THROUGH

Your image belongs
in your application’s
declared state.

Apply an Image with a version and production recipe. The controller manages the attempts, verification, and publication needed to make it available.

Compare the approaches ↗
01

Declare the outcome

The Image is the durable resource. Build attempts are execution details managed by the controller, with retries and recovery.

02

Keep publication close

A PVC-backed OCI registry is part of the installation. Application images need no separate output registry URL or push credentials. External export is optional.

03

Give releases their own lifetime

Verified releases remain available after input objects are removed or builder caches are cleared. A published version cannot be replaced with different content.

VERSION SELECTION THAT READS WELL

A name you recognize.
A digest you can trust.

Use exact versions for uniform rollouts, ranges for compatible releases, or a channel you explicitly map. Each new Pod gets a concrete digest.

Selectors resolve at Pod creation. Publishing a release does not restart existing workloads. Consumption is currently restricted to the same namespace.
