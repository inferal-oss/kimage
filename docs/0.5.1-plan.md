# 0.5.1 plan: Argo CD installation

Status: implementation and acceptance in progress for 0.5.1. See the
[Argo CD installation contract](argocd.md). The original acceptance scope is
preserved below; public results will record the checks actually completed.

Make a small Argo CD `Application` enough to install and maintain kimage from
the published Helm repository, with namespace and cluster scope supported.
Keep the normal CLI and Helm paths working.

## Current gaps

The 0.5.0 chart queries live Nodes, installation records and credentials through
Helm `lookup`. It also generates random credentials and certificates during
rendering. Argo CD uses Helm to render manifests rather than manage a Helm
release, so the existing chart is not yet an Argo CD installation contract.
An Application example alone would not resolve those differences.

## Required changes

- Make rendering deterministic and independent of cluster access. Discover
  native nodes and perform runtime checks inside the cluster. Keep placement
  automatic without putting full Node objects in Git.
- Generate missing credentials once in the cluster, preserve their identities
  across repeated syncs and restarts, and support explicitly supplied Secret
  references. Do not require private keys or passwords in Git.
- Define Argo CD ownership separately from a Helm-managed release. Reconcile
  operator-created workers, proxies and readiness resources without perpetual
  drift, competing controllers or broad `ignoreDifferences` rules.
- Order bootstrap, CRDs, credentials, registry, workers and admission safely.
  Expose readiness and failures through Application health. Review hooks and
  sync waves against real Argo CD behavior, including retries and pruning.
- Route version changes through the guarded transition contract with its Lease,
  journal, compatibility checks and resumability. A changed `targetRevision`
  must not bypass upgrade or rollback protection. Starting with 0.5.1, a returning
  older chart automatically delegates compatible downgrades to the installed newer
  operator by digest. Test this with actual separate future-version binaries and
  chart, including interrupted provisioner/helper recovery.
- Preserve registry data, Images, ImageReleases and shared CRDs on Application
  deletion and pruning. Use explicit Argo CD retention semantics rather than
  relying only on Helm's resource retention annotation. Document intentional
  data deletion separately.
- Provide copyable Applications for both scopes using `https://kimage.dev/charts`,
  an exact chart version and a short `valuesObject`. Include prerequisites,
  configuration, health inspection, upgrade, rollback and removal guidance.
  Update README, website docs, quickstarts, `llms.txt` and changelog when shipped.
- Document whether adopting an existing CLI/Helm installation is supported. If
  supported, require a checked ownership handover that preserves storage and
  credentials; never claim automatic adoption without testing it.

## Acceptance

Test with an actual Argo CD controller, not just `helm template`:

1. Repeated offline renders are identical with no credentials supplied, and do
   not require a Kubernetes API connection.
2. Fresh namespace and cluster installs become Healthy and Synced. Repeated
   sync, automatic self-heal and controller restart preserve credentials,
   retained storage identity and administrator build policy.
3. New nodes and a newly available architecture receive the correct native
   worker/proxy resources without making the Application permanently OutOfSync.
4. Fresh unknown-placement and explicitly placed Images build and run through
   native GHCR components on amd64 and arm64, including the real mixed cluster.
5. Supported version transitions, interrupted syncs and rollback resume safely;
   conflicting operations and unsupported transitions fail without data loss.
6. Pruning and Application deletion preserve retained resource identities and
   image bytes; reinstall can consume existing releases.
7. Existing CLI and Helm lifecycle acceptance continues to pass.

Use ordinary CI for deterministic rendering and Argo CD lifecycle cases. Keep
the real mixed-cluster case explicitly enabled, with a separate recorded result.
